DEFAULTS
Typography: Source Serif 4 headings; Inter body, labels and controls. The native heading family is RR Serif. Fonts/Kozu-SourceSerif4.ttf supplies that alias as an unchanged copy of the authoring font; see Fonts/README.md for setup after cloning. Apps may explicitly override the font family.
Icons: Aria Icons, https://icons.leularia.com/. Use one coherent Lucide line collection by default. Icons contains the SVG assets, source IDs and upstream license. Preserve semantic icon strokes and checkmarks when removing outer state borders. Aria is a catalog; check the selected collection's license when adding icons.
Materials: circular top actions, icon-only floating toolbars and selected surfaces use frosted backing with sampled background blur. Default control blur is 28 logical units; menu/overlay blur is 40. Increase backing opacity or use a solid fallback over busy content and for reduced transparency. Content panels remain stable reading surfaces.
Geometry: innerRadius = max(0, outerRadius - inset). Keep nested circles concentric. Use symmetric container padding and centered icon targets. Derive each inner radius from its actual inset.
Centering: in text buttons, match the paired icon's optical height (actual visible ink) to the label's cap height at its font, size and weight. The icon frame, font size and line height are not the matching measurement. Center icon and label vertically; balance leading and trailing slots to keep the label centered within the whole button. Keep the icon-only default at a 24-unit icon in a 48-unit target and retain larger platform hit areas. Center icons within chips, navigation targets and toolbar cells, with only explicit optical corrections for asymmetric glyphs.
Paired icon geometry: measure button-local coordinates from the top-left. Leading visible-ink center = (buttonHeight / 2, buttonHeight / 2); trailing visible-ink center = (buttonWidth - buttonHeight / 2, buttonHeight / 2). Each matches the rounded endcap center, as if an invisible circle of diameter buttonHeight occupied that end. Position the visible ink, not just its frame. Keep the whole label centered at (buttonWidth / 2, buttonHeight / 2), with balanced end slots and icon ink sized to label cap height. The circle is a placement guide; draw no extra circle or border. This rule also applies to TV text buttons; retain the large hit areas.
States: no outer state, focus, selected or pressed borders anywhere. Keyboard and TV remote focus use native tone, lift or scale; selection retains its own tint/checkmarks and selected semantics. Press uses tone/fill. Reduced motion uses static tone and text weight, with no animated zoom, scale or parallax. Keep focus visible independently from selection.

COLOR CONFIGURATION
Use Kozu / navigation policy to choose Shared accent or Per tab. Shared accent resolves every destination to the app accent. Per tab resolves each destination to its configured color. Set Kozu / accent theme to Blue, Violet, Orange, Teal, Rose, Amber, Sky or Emerald, then set destination scopes as needed.
The selected icon and tinted background resolve from the same accent. Light selections mix 16% accent with light backing; dark selections mix 32% accent with neutral dark backing. Change foreground and selected background together. Page 19 compares both policies; page 24 defines color roles and states.
The palette uses Tailwind-inspired RGB families, without claiming exact Tailwind version parity. Semantic roles remain separate from decorative accents: green for success, amber for caution, red for error/destructive actions, sky for information. Status messages also include a label, icon or shape.
Kozu.tokens.json includes readable roles, resolved pairs, geometry rules, platform guidance and the exact native variable export. Component inventory.json records master IDs and exposed properties.

LIGHT AND DARK VISIBILITY
Page 25 includes examples and rules for both modes. Use semantic foreground/background pairs. Target WCAG contrast of 4.5:1 for normal text, 3:1 for large text and essential control graphics. Disabled states must remain understandable, although inactive controls have different contrast requirements.
Test frosted controls over the lightest, darkest and busiest expected backdrops. Increase backing opacity before increasing blur. Provide a solid reduced-transparency fallback. Do not depend on shadows alone for separation in dark mode. Show focus, selection, validation and disabled behavior independently.

ADAPTIVE RULES
Below 600: compact navigation and one primary content pane.
600–719: rail plus one content pane; details replace the master list when necessary.
720–839: rail plus master/detail only if a 240-unit master and a detail pane of at least 280 units both fit.
840+: sidebar; add panes only when each minimum width fits. The overview inspector begins at 1100.
Preserve selected records, drafts and scroll position across layout changes. Keep workspace navigation separate from record actions. Respect native window controls, safe areas, IME behavior and platform shortcuts.

WIDGET AND WEARABLE SIZING
Android is the primary widget reference. The illustrated grid uses an 82dp cell and 16dp gap: 2x2 = 180x180, 4x1 = 376x82, 4x2 = 376x180, 4x4 = 376x376. These are representative canvases; launcher-provided bounds and resize ranges are authoritative. Home-screen widgets cannot reproduce application backdrop blur on every host.
Apple examples use standard widget families, with representative device rows documented on page 31. Dimensions vary by device, OS and host. Use WidgetKit family bounds and system margins instead of hardcoding preview dimensions.
Wear OS round canvases and Apple Watch canvases are logical design references, not physical device pixel specifications. Validate round-screen safe regions. Apple Watch faces are concepts: deliver supported app views and complication families; this kit does not imply unrestricted third-party system watch-face installation.
TV uses a tvOS-inspired centered top navigation row and full-bleed image cards. The 1440×810 preview uses 300×168.75 cards (16:9); the focused card is 318×178.875 (1.06×). The image reaches every card edge, with no inset thumbnail or separate opaque text panel. A bottom-up dark scrim is transparent through 25% of card height, reaches 82% black at 60%, and 94% at the bottom. Place titles and metadata below 60% and check at least 4.5:1 contrast against the actual composited image; strengthen the scrim or use an opaque fallback when needed. The contrast threshold is an acceptance requirement, not a claim that all imagery has passed.
TV text-button labels use Inter at 22 logical units, like the top category labels. Match the paired icon's actual ink height to the label's cap height and center both vertically. Balance icon slots to keep the label centered within the whole button; keep the large hit area.
TV focus uses native tone/lift/scale while persistent selection retains tint/check. Reduced motion uses static tone and text weight, with no animated zoom. Check directional movement, focus return, Back behavior, viewing-distance legibility and safe regions on target hardware. The 72-unit preview side inset maps to 96 pt at 1920 width, exceeding Apple's 80 pt side guidance. Verify top/bottom safe areas separately; native framework safe areas and focus geometry are authoritative. The centered navigation, card sizes and scrim stops are Kozu choices, not mandatory Apple dimensions. Official Apple references are recorded in Platform references.json.

EDITION 0.4 DEFAULTS
Light canvas: #FCFCFC. White containers sit above the near-white base. Shared accent is the default per app; cards, chips, actions, avatars and selection marks inherit that family. Per-tab palettes are opt-in. Neutralize a card or derive its tint from the local action when deliberately using another accent. Unrelated decorative accent fills should not touch. Status colors and meaningful data categories retain their explicit roles.
Rail items: 56-unit circles, 24-unit icons at (16,16), 8-unit gaps, centered in an 88-unit rail. Avatars expose Initial and center Inter text in a 56-unit circle. Geometry checks cover rail targets, initials, chips and whole-button labels.
Frost backing is reduced by 10 percentage points: controls about 58% light/65% dark, toolbars 62%/70%, overlays 84%. The heavy 28/40-unit blur remains. Pale checkbox/radio/mixed fills use clear accent marks rather than opaque saturated state blocks. Blue and orange foreground tones are stronger to retain label contrast.
Wear OS uses ScreenScaffold, TransformingLazyColumn, SurfaceTransformation and native EdgeButton geometry. Rows and their text transform together. Edge-button text follows native reveal height; add no delayed custom text fade or separate scroll entrance delay. FadingExpandingLabel is for changing multiline content, not scroll reveal. Respect LocalReduceMotion; reduced-motion focus uses static tone and text weight without animated zoom. Keep native typography and native device/font-scale previews. The FigCraft transition is a simulation; it does not prove native continuous-scroll behavior.
Wear OS and Android home widgets exclude portable backdrop blur by default and use native tonal surfaces. Apple widgets use host-provided Liquid Glass only where supported by the chosen appearance and rendering mode; retain full-color and accessibility fallbacks. Tiles do not scroll.
The latest critique addressed mixed navigation/actions, duplicate creative tools, chart units/values, a conflicting music playhead, watch-label alignment and a missing error icon. New guidance is on pages 37–38. Dynamic imagery still needs implementation-specific contrast and performance checks. No static kit can prove all runtime metrics.
