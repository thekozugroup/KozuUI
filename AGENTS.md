# Kozu app system defaults

Use `Kozu Universal UI Kit.figcraft` as the editable design reference and `Kozu.tokens.json` as the portable token reference. This is a design foundation; implement and test native behavior in each app.

Canonical GitHub repository: https://github.com/thekozugroup/KozuUI. Use the local checkout at `/Users/michaelwong/Developer/KozuUI` (`~/Developer/KozuUI`). The user has authorized work on `main`.

- Default typography: Source Serif 4 for headings; Inter for body text and controls. The installed heading font is internally named `RR Serif` in FigCraft. Preserve these defaults unless a platform or app explicitly overrides them for legibility or framework support.
- Default icon provider: https://icons.leularia.com/ (Aria Icons). Use one coherent collection; this kit uses Lucide line source icons on a 24-unit grid with a 1.8-unit stroke. Size text-paired icons by their visible ink as specified below. Preserve semantic icon strokes, checkmarks and the included upstream license. Removing state borders must not remove these meaningful strokes. Do not mix packs without a specific reason.
- Light canvas is near-white `#FCFCFC`, with white containers. Use one accent family per app by default. Cards, chips, actions and selected marks inherit it; per-tab colors are opt-in. Separate a deliberately different local accent with a neutral card or derive the card tint from that same accent.
- Use frosted backgrounds on circular top actions, floating action toolbars, selected controls, menus and transient overlays. Keep content mostly opaque. Default blur is 28 logical units; overlay blur is 40. Raise tint opacity or use an opaque fallback when contrast or performance requires it.
- Frost backing is 10 percentage points lighter than the initial edition: control about 58% light/65% dark; toolbar 62%/70%; overlay 84%. Keep foreground contrast. Selected checkbox/radio/mixed states use pale accent fills and clear accent marks, without a selected border.
- Do not add outer state, focus, selected or pressed borders anywhere in the kit. Keep keyboard and remote focus visible through native tone, lift or scale, independently from persistent selection tint/checkmarks and selected semantics. Press uses tone/fill. Reduced motion uses static tone and text weight, with no animated zoom, scale or parallax.
- Choose Tailwind-inspired accent families independently from semantic status: success uses green/emerald, warning amber, error/destruction red, and information sky. Always pair status with an icon and clear words.
- Configure `Kozu / navigation policy` at app scope: `Shared accent` or `Per tab`. Set each item's destination mode. The selected icon and its background tint must derive from the same resolved color; per-tab light/dark colors are configured in the accent theme. Use a neutral dark backing to preserve hue.
- In text buttons, match the paired icon's optical height (actual visible ink) to the label's cap height at its font, size and weight; do not match the icon frame to the font size or line height. Center icon and label vertically. Balance leading and trailing slots to keep the label centered within the whole button. Keep the icon-only default at a 24-unit icon in a 48-unit target; retain larger platform hit areas. Center icon-only content in its target and chip content in its capsule. TV text-button labels use Inter at 22 logical units, like the top category labels, with icon ink matched to that cap height; keep the large hit areas.
- For paired icons, use button-local coordinates from the top-left: leading visible-ink center = `(buttonHeight / 2, buttonHeight / 2)`; trailing visible-ink center = `(buttonWidth - buttonHeight / 2, buttonHeight / 2)`. Each center coincides with the rounded endcap center, as if an invisible circle of diameter `buttonHeight` occupied that end. Position the visible ink, not just its frame. Keep the whole label centered at `(buttonWidth / 2, buttonHeight / 2)` with balanced end slots. Size icon ink to label cap height. The circle is a placement guide; draw no extra circle or border.
- Rail items are 56-unit circles with 24-unit icons at (16,16), 8-unit gaps and centered placement in an 88-unit rail. Avatar initials use the exposed `Initial` property and center in a 56-unit circle.
- Enforce concentricity: adjacent nested curved edges use `innerRadius = max(0, outerRadius - inset)`. Keep toolbar end padding symmetric, center selected shapes, and leave room for native focus lift/scale without clipping adjacent content. Run `python3 tools/verify_geometry.py --self-test` and `python3 tools/verify_geometry.py` after editing the native kit.
- Keep destinations in the bottom navigation, rail or sidebar; TV uses one centered top navigation row inspired by tvOS. Floating contextual actions operate on the selected content. Avoid duplicated destination controls.
- Adapt to window width: compact below 600; rail at 600; two content panes only at 720 or above when minimum widths fit; sidebar at 840; extra detail/inspector panes only when sufficient width remains. Preserve selection, scroll and unsaved input.
- Default touch target: 48 logical units. Compact pointer density is an explicit option, with a 32-unit minimum target. Respect safe areas, IME insets, native window decorations and platform keyboard conventions on Android, Googlebook, Linux and macOS.
- TV uses larger targets, readable distant typography, predictable remote focus and full-bleed image cards. The 1440×810 preview uses 300×168.75 cards (16:9), focused at 318×178.875 (1.06×). Use a bottom-up dark scrim: transparent through 25% of card height, 82% black at 60%, 94% at the bottom. Place titles and metadata below 60%; verify at least 4.5:1 contrast over actual imagery. The 72-unit side inset corresponds to 96 pt at 1920 width, exceeding Apple's 80 pt side guidance; native framework safe areas and focus geometry are authoritative. Check vertical safe areas separately. Wear OS uses round-safe content; Apple Watch uses its native rectangular families and Crown behavior. Widgets use Android host grid spans or Apple widget families, with exact bounds supplied by the host.
- Wear OS uses native `ScreenScaffold`, `TransformingLazyColumn`, `SurfaceTransformation` and bezel-following `EdgeButton`. Rows and their text transform together; edge-button text follows native reveal height. Add no delayed custom text fade or separate scroll entrance delay. Use `FadingExpandingLabel` for changing multiline content only. Respect native reduced motion, typography and touch/rotary defaults. FigCraft motion previews are simulations.
- Exclude portable backdrop frost from Wear OS and Android widgets by default; use native tonal surfaces. Apple widgets use host-provided glass only in supported appearances, with full-color and accessibility fallbacks. Tiles do not scroll.
- Prefer instances of existing masters and semantic variables. Modify app theme modes before forking components. Preserve labels, error/help text, focus behavior, text wrapping and minimum targets.
- Verify accessible names, keyboard traversal, focus return, 200% text, constrained windows and real blur performance in the implementation. Static FigCraft boards do not prove these runtime behaviors.
- After importing native files, verify variable collections and remap all imported bindings. This FigCraft version can import layers without their variable definitions; never accept a visually incorrect color caused by colliding token IDs.
